==================================================
2. THE TRIAD CONTRACT — WHY YOU CAN TRUST THE SELECTION
==================================================

Stage 5 uses an evidence-mode-aware deterministic selector:

  evidence_mode = "qualitative" or "none"
    → composition is ALWAYS broll_caption
    → no numeric values are needed or expected

  evidence_mode = "single_value"
    → composition is metric_hero
    → exactly ONE measurement is present in the intent

  evidence_mode = "time_series" or "multiple_values"
    → composition is growth_trajectory, time_decay, comparison_split, trajectory_divergence, etc.
    → multiple measurements are present in the intent

  evidence_mode = "calculation_inputs"
    → composition is calculation_story
    → input and result measurements are present in the intent

This means: when you receive a numeric composition (growth_trajectory, metric_hero, etc.), the measurements EXIST in the VisualIntent. Extract them. Do not hallucinate.

When you receive broll_caption, no numeric values are needed. Focus on the caption text and asset queries.

==================================================
3. EXTRACTION HIERARCHY — WHERE TO FIND DATA
==================================================

Look for values in this exact priority order:

1. intent.measurements[] — primary source for all numeric values
   - Use raw_value for display (e.g. "₹1,50,000", "67%", "1,000 tonnes")
   - Use role to identify which measurement is which: "input", "rate", "result", "baseline", "delta", "benchmark"
   - Use entity_name and metric_name to derive labels

2. intent.comparison — for comparison_split and trajectory_divergence
   - subject_a / value_a → left side
   - subject_b / value_b → right side
   - comparison_dimension → comparison_label
   - delta → delta field

3. intent.causal — for cause_effect and multi_factor_pressure
   - causes[] → cause cards
   - outcome → outcome_label
   - mechanism → outcome_note

4. intent.temporal — for time fields
   - horizon → time_period / time_horizon
   - start_point / end_point → for ranges

5. intent.entities[] — for label fallbacks when measurements lack entity_name
   - role: "subject", "baseline", "alternative", "risk_factor"

6. intent.what_viewer_must_understand — for caption text in broll_caption

7. intent.visual_dynamics.focal_point — for annotations, header labels, emphasis

If a field has no supporting evidence in any of the above, leave it null. Do not invent it.

==================================================
4. VALUE vs LABEL ARCHITECTURE
==================================================

Remotion components render values and labels in different typographic hierarchies.

A. VALUE FIELDS — strictly quantitative
(value, start_value, end_value, left_value, right_value, result_value, input_value, fixed_amount, delta, total_value, loan_amount, divergence_gap)

- Format with appropriate currency, unit, or sign:
  * Currency: "₹1,00,000" | "₹50 Lakh" | "₹1.5 Crore"
  * Percentages: "67%" | "8.5%"
  * Multipliers: "3x" | "2.5x"
  * Signed deltas: "+₹10,000" | "+67%" | "-₹5,000"
  * Timeframes: "10 Years" | "Over 20 Years"

- Extract from measurements[].raw_value directly — do not reformat unless necessary for clarity.
- If a value field has no corresponding measurement, set it to null (do NOT invent a number).
- NEVER put qualitative words into value fields: "Bulk", "High", "Better", "Growth" are forbidden in value slots.

B. LABEL FIELDS — short editorial descriptions
(label, start_label, end_label, left_label, right_label, input_label, result_label, amount_label, baseline_label, header_label)

- Derive from entity_name, metric_name, or context in the VisualIntent.
- Short, punchy title phrases: 2–4 words maximum.
  * "Monthly Take-Home" | "Automated SIP" | "10-Year Corpus" | "ETF Inflows"
- Labels CAN be editorially crafted — they describe what a value represents.
- NEVER duplicate the value in the label: if value="₹10,000", label="Monthly Raise" (not "₹10,000").

==================================================
5. NULL POLICY
==================================================

Null is correct when no evidence exists. Never manufacture a value to fill a slot.

- REQUIRED fields with no evidence: this should not happen (Stage 5 selected the composition because the evidence exists). If it somehow does, use the narration excerpt and what_viewer_must_understand to derive a reasonable label — but do not invent a number.
- OPTIONAL fields with no evidence: set to null or omit entirely.
- FORBIDDEN placeholders: "N/A", "TBD", "Unknown", "Placeholder", "Not available", "Target Corpus", "Starting Point", "Original Value" are strictly forbidden in any factual field.

==================================================
6. COMPOSITION FAMILY RULES
==================================================

### broll_caption
- caption: Use intent.what_viewer_must_understand verbatim or lightly edited.
- emphasis_phrase: Use intent.visual_dynamics.focal_point or a key phrase from the narration. Keep it under 6 words.
- asset_queries: 2–3 concrete stock footage search queries (2–5 words each).
  * GOOD: "person reviewing financial documents" | "gold coins close up" | "stock market chart screen"
  * BAD: "growth concept" | "money freedom" | "investor understanding market" | "car driving" (unless topic is auto loans)
  * Describe tangible, visible scenes relevant to the narration topic.
  * Never use abstract, cartoon, CGI, or unrelated queries.

### metric_hero
- value: Extract from measurements[0].raw_value (the single focal metric).
- label: Derive from measurements[0].metric_name or entity_name (2–4 words).
- direction: "up" for positive/growth, "down" for decline/loss, "flat" for neutral. From measurements[0].direction.
- polarity: "positive" | "negative" | "neutral" | "warning". From measurements[0].polarity.
- delta: Only if a second measurement with role="delta" exists. Otherwise null.
- context: Short timeframe or context phrase from intent.temporal.horizon or intent.temporal.frequency.

### growth_trajectory
- start_value: From measurements where role="input" or role="baseline". Use raw_value.
- start_label: From that measurement's entity_name or metric_name.
- end_value: From measurements where role="result" or role="final". Use raw_value.
- end_label: From that measurement's entity_name or metric_name.
- growth_rate: From measurements where role="rate". Use raw_value.
- time_horizon: From intent.temporal.horizon.
- All of these can be null if no matching measurement exists — do NOT invent endpoints.

### time_decay
- fixed_amount: From measurements where role="baseline" or role="input". Use raw_value.
- amount_label: Entity/metric name for what is decaying.
- time_period: From intent.temporal.horizon.
- drop_rate: From measurements where role="rate" or role="delta". Use raw_value.
- end_value: From measurements where role="result". Use raw_value if present, otherwise null.
- Null fields are acceptable — do not manufacture a fictional decay amount.

### comparison_split
- left_role: From intent.comparison.subject_a or entities[0].name.
- right_role: From intent.comparison.subject_b or entities[1].name.
- left_value: From intent.comparison.value_a (null if qualitative).
- right_value: From intent.comparison.value_b (null if qualitative).
- comparison_label: From intent.comparison.comparison_dimension.
- delta: From intent.comparison.delta.

### trajectory_divergence
- baseline_label: From intent.comparison.comparison_dimension or entities[0].name.
- path_a.label: From intent.comparison.subject_a.
- path_a.end_value: From intent.comparison.value_a (null if no numeric value exists).
- path_a.direction: "up" for favorable/investing paths.
- path_a.tone: "positive" for growth/wealth paths.
- path_b.label: From intent.comparison.subject_b.
- path_b.end_value: From intent.comparison.value_b (null if no numeric value exists).
- path_b.direction: "down" for decline/spending paths.
- path_b.tone: "negative" for debt/lifestyle-creep paths.
- divergence_gap: From intent.comparison.delta (null if not present).

### cause_effect
- causes: 1–3 items from intent.causal.causes[]. Each item: {"label": "..."}. Label = the cause verbatim or lightly condensed to 3–5 words.
- connector: A verb phrase linking cause to outcome: "leads to" | "creates" | "enforces" | "drives" | "results in".
- outcome_label: From intent.causal.outcome. Short, 3–5 words.
- outcome_note: From intent.causal.mechanism. Optional explanatory text.
- outcome_severity: "negative" | "positive" | "neutral" | "warning". From intent.causal.outcome_severity.

### multi_factor_pressure
- factors: 2–4 items from intent.causal.causes[]. Each: {"label": "...", "value": null_or_measurement}.
- combined_label: From intent.causal.outcome.
- combined_severity: From intent.causal.outcome_severity.

### calculation_story
- input_value: From measurements with role="input" or role="baseline". Use raw_value.
- input_label: entity_name or metric_name of that measurement (2–4 words).
- rate_label: From measurements with role="rate". Use raw_value (e.g. "10% Annual Return").
- result_value: From measurements with role="result". Use raw_value.
- result_label: entity_name or metric_name of result measurement (2–4 words).
- operation_label: Short operator symbol or word: "×" | "+" | "minus" | "→" | "yields".
- timeframe: From intent.temporal.horizon.

### cash_flow_waterfall
- starting_value: From measurements with role="baseline". Use raw_value.
- starting_label: Entity/metric name (e.g. "Monthly Gross Salary").
- steps: Each deduction from measurements with role="delta". {"label": "...", "value": "-₹X,XXX", "direction": "subtract"}.
- final_value: Only if deterministically calculable from the measurements. Otherwise null.
- final_label: "Net Savings" | "Remaining Balance" or similar.

### accumulation_decomposition
- total_value: From measurements with role="result". The final accumulated total.
- total_label: What the total represents (e.g. "10-Year Corpus").
- streams: 2–4 contribution streams from measurements. Each: {"label": "...", "value": "...", "direction": "add"}.
- time_horizon: From intent.temporal.horizon.

### debt_amortization_schedule
- loan_amount: From measurements with role="input" or role="baseline". Use raw_value.
- loan_label: What the loan is for (e.g. "Home Loan" | "Car EMI").
- interest_rate: From measurements with role="rate". Use raw_value.
- tenure: From intent.temporal.horizon.
- payment_amount: Monthly EMI if present in measurements. Otherwise null.

### ranked_list
- items: 2–5 items from intent.entities[]. Each: {"title": entity.name, "rank": index+1, "value": matching measurement raw_value or null}.
- header_label: From intent.visual_dynamics.focal_point or "Key Factors".

### process_flow
- steps: 2–5 steps from intent.entities[] in sequential order. Each: {"title": entity.name, "subtitle": entity.role if descriptive, "type": "step"}.
- header_label: From intent.visual_dynamics.focal_point or derived from narration.

==================================================

==================================================

Enum fields must strictly match the allowed literals:
- direction: "up" | "down" | "flat" | "neutral"
- polarity: "positive" | "negative" | "neutral" | "warning"
- emphasis: "hero" | "supporting"
- variant: only from the schema's allowed values — do not invent variants

Do not use synonyms like "increasing", "declining", "bullish", "bearish".
