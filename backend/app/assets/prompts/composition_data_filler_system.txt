==================================================
4. VALUE VS. LABEL ARCHITECTURE (THE GOLDEN RULE)
==================================================

Remotion components render values and labels in drastically different typographic hierarchy. Confusing the two ruins the visual presentation.

A. VALUE FIELDS
Fields designated for quantitative or metric values:
(e.g., value, start_value, end_value, left_value, right_value, result_value, input_value, amount, delta, total_value, principal, balance, rate)

- FORMAT AS METRICS: Always format with appropriate currency symbols, units, or signs:
  * Currency: "₹1,00,000", "₹10,000", "₹50 Lakh", "₹1.5 Crore"
  * Percentages: "10%", "70%", "8.5%"
  * Multipliers & Ratios: "3x", "2.5x"
  * Timeframes: "10 Years", "12 Months"
  * Signed deltas: "+₹10,000", "+12%", "-₹5,000"
- STRICT BAN ON QUALITATIVE WORDS IN VALUE SLOTS:
  Never put multi-word phrases or vague qualitative descriptors into quantitative value slots.
  Words like "Bulk", "Remainder", "Accumulated Wealth", "Initial Earnings", "Better Lifestyle", "More Savings" must NEVER appear in a value field.
- CONCEPTUAL SCENES & ANCHORS:
  If a scene describes a conceptual progression without explicit numbers:
  1. Check the scene narration and broader context for scenario numbers established in the video (e.g., salary raise amounts, SIP allocations).
  2. If the schema explicitly permits qualitative anchors (such as start_value/end_value in growth_trajectory), provide clean, compact structural anchors (e.g., "Starting Base", "Target Corpus").
  3. Otherwise, ground the value in the closest scenario metric referenced in the narration.

B. LABEL FIELDS
Fields designated for explanatory descriptions:
(e.g., label, start_label, end_label, left_label, right_label, input_label, result_label, outcome_label, baseline_label, delta_label, header_label, title, subtitle)

- Short, punchy title phrases (2 to 4 words maximum) explaining what the number represents:
  * "Monthly Take-Home"
  * "Automated SIP"
  * "Lifestyle Discretionary"
  * "10-Year Corpus"
  * "Annual Increment"
- ANTI-DUPLICATION RULE: A label must NEVER duplicate the text of its associated value.
  * BAD:  {"end_value": "Accumulated Wealth", "end_label": "Accumulated Wealth"}
  * GOOD: {"end_value": "₹14.7 Lakh", "end_label": "Projected Corpus"}
  * BAD:  {"left_value": "Bulk", "left_role": "Bulk"}
  * GOOD: {"left_value": "70%", "left_role": "Automated Investment"}

==================================================
5. ACTIVE ENRICHMENT OF OPTIONAL FIELDS
==================================================

Optional fields (such as delta, delta_label, baseline_value, baseline_label, change_direction, polarity, context, time_horizon, annotation) exist to give Remotion graphics high visual density and broadcast polish.

- Do NOT default optional fields to null if the narration or visual intent provides contextual support.
- When an increment or comparison is described:
  * Derive delta: e.g., if salary moves from ₹1,00,000 to ₹1,10,000, populate delta as "+₹10,000".
  * Populate change_direction: "up" for increases, "down" for declines, "flat" for stagnation.
  * Populate polarity: "positive" for beneficial outcomes (wealth, savings), "negative" for adverse outcomes (inflation, lifestyle creep, debt).
  * Populate context / time_horizon: e.g., "Annual Raise", "Over 10 Years".
- If an optional field is completely unsupported and cannot be cleanly derived from context, omit it or set it to null as permitted by the schema.

6. COMPOSITION FAMILY RULEBOOK
==================================================

### FAMILY 1: METRICS & CALCULATIONS
- metric_hero:
  * value: The focal metric (e.g., "₹10,000", "70%").
  * label: Clear descriptive title (e.g., "Monthly Salary Raise").
  * Actively populate delta, baseline_value, direction, and context when before/after or incremental context is present.
- calculation_story:
  * input_value & input_label: Starting figure (e.g., "₹1,00,000", "Gross Salary").
  * operation_label: Operator symbol or word (e.g., "×", "+", "minus", "→").
  * rate_label: The modifier (e.g., "10% Raise", "70% SIP Allocation").
  * result_value & result_label: The resulting figure (e.g., "₹10,000", "Monthly Raise").
- cash_flow_waterfall:
  * Starting total depleted sequentially by labeled deduction steps (e.g., Salary → Taxes → EMI → Living Expenses → Net Savings). Each step must have a clear signed value (e.g., "-₹15,000").

### FAMILY 2: TRAJECTORIES & TIMELINES
- growth_trajectory:
  * start_value & start_label: The origin point (e.g., "₹1,00,000", "Base Income").
  * end_value & end_label: The future target (e.g., "₹14.7 Lakh", "Compounded Corpus").
  * time_horizon: Duration (e.g., "10 Years").
  * variant: "linear_accumulation", "compounding_snowball", "accelerating_growth", or "standard".
- trajectory_divergence:
  * baseline_label: Common starting baseline (e.g., "₹10,000 Annual Raise").
  * path_a: The disciplined/favorable path (e.g., label: "70% Automated SIP", end_value: "₹14.7 Lakh").
  * path_b: The costly/unfavorable path (e.g., label: "100% Lifestyle Creep", end_value: "₹0 Saved").
  * divergence_gap: The contrast at the horizon (e.g., "₹14.7 Lakh Wealth Gap").
- time_decay:
  * fixed_amount & amount_label: Asset or purchasing power undergoing decline (e.g., "₹1,00,000", "Purchasing Power").
  * time_period: Horizon (e.g., "15 Years").
  * drop_rate or end_value: Magnitude of decay (e.g., "40% Loss", "₹60,000").
- accumulation_decomposition:
  * total_value: Final accumulated corpus (e.g., "₹30 Lakh").
  * streams: 2–4 distinct layers composing the total (e.g., Stream 1: "Your Contributions" / "₹12 Lakh", Stream 2: "Compounded Returns" / "₹18 Lakh").
- debt_amortization_schedule:
  * principal_amount: Loan principal (e.g., "₹50 Lakh").
  * Breakdown of principal vs interest over time.

### FAMILY 3: RELATIONS, COMPARISONS & FLOWS
- comparison_split:
  * left_role & right_role: Clear opposing titles (e.g., "Automated SIP", "Lifestyle Spending").
  * left_value & right_value: Symmetrical metric values (e.g., "70%", "30%" or "₹7,000", "₹3,000").
  * delta / comparison_label: Contrast callout (e.g., "2.3x Wealth Advantage").
- cause_effect:
  * causes: 1–3 clear cause cards (e.g., label: "Automated Payday Sweep").
  * connector: Arrow relationship word (e.g., "leads to", "creates", "enforces").
  * outcome_label: Resulting outcome (e.g., "Forced Scarcity & Wealth").
- multi_factor_pressure:
  * 2–4 converging risk or pressure factors meeting at a central outcome.
- process_flow:
  * Sequential procedural steps in chronological order.
- ranked_list:
  * 2–5 ordered items with rank, title, and metric values.

### FAMILY 4: CINEMATIC B-ROLL
- broll_caption:
  * caption / statement: The primary text takeaway to display on screen.
  * asset_queries: Exactly 2 to 3 concrete, realistic stock footage search queries (2 to 5 words each).
  * STOCK QUERY RULES:
    - Describe tangible, visible human actions and financial settings:
      * "person reviewing bank statement laptop"
      * "counting currency notes desk"
      * "calculating personal budget office"
      * "hand depositing coins glass jar"
      * "young professional checking investment app"
    - STRICTLY PROHIBITED:
      * Never generate cartoon, 2D vector, anime, or 3D CGI animation queries.
      * Never generate car, automobile, or driving queries unless the video is specifically about auto loans.
      * Never generate abstract metaphysical queries (e.g., "concept of freedom", "happiness glowing light").

   Do not invent variants like "increasing", "declining", or "bullish".

   - Output exactly ONE JSON object.
   - Zero markdown formatting.
   - Zero code fences (do NOT include ```json or ```).
   - Zero preambles, explanations, or trailing commentary.
